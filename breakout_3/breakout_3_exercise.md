## Part 3 - AI を活用したオブザーバビリティ
#### Grafana Assistant を使って同じ根本原因を見つける方法

この演習では、前のセクションと同じトラブルシューティングシナリオに取り組みます。ただし今回は、AI ツール、特に [Grafana Assistant](https://grafana.com/docs/grafana-cloud/machine-learning/assistant/) を使って解決策を見つけます。

### 手順

この演習では、__パート 1 と同じ環境__を使用します。スライドに記載されているパート 1 環境の URL にアクセスしてください。そこでは、以下を含む Grafana Cloud Stack を利用できます。
1. Frontend O11y
1. App O11y
1. K8s Monitoring

右上の Grafana Assistant ボタンをクリックして開始します。以下の各セクションでは、コンテキストと質問の継続性を保つために、同じプロンプトウィンドウを使用します。ただし、セクションを切り替える際は新しいプロンプトウィンドウを開くことをお勧めします。そうすることで、Assistant がリクエストをどのように処理するかを確認できます。実際の業務では、一連の質問や調査には同じプロンプトを使い続けるのが効果的です。
![grafana-assistant](/images/breakout_3/0.1-grafana-assistant.png)

質問に取り組む時間は 20 分です。その後、最後の 10 分間で全員で一緒に振り返ります。コアの質問を優先してください。時間があればエクストラクレジットにも取り組みましょう。

解答と解説は [breakout_3_answers](./breakout_3_answers) フォルダにありますが、まず自分で取り組んでみることをお勧めします。

___注意___: LLM アシスタントの応答は可変であるため、ユーザーによって結果が異なったり、前の演習で得た結果と一致しなかったりすることがあります。Assistant が意図した動作をしない場合は、プロンプトを追加して正しい方向に誘導してください。

### 注目すべき点

**Assistant のツール使用** が表示されたとき

* LLM はハルシネーション（幻覚）を起こすことがあるため、すべての処理過程を表示しています
* クリックで展開できます \- Assistant の思考過程を確認することで、結論の信頼性を判断できます

**Assistant のエラー** が表示されたとき

* Assistant も人間と同様にミスをします。そのエラーを LLM にフィードバックすることで、再考して改善できるようにしています
* Grafana Assistant が結論を出せない場合は、通常その旨を伝えてきます（ただし、長時間試みた後になります）

**グラフやログの可視化** が表示されたとき

* Assistant は単に情報を伝えるだけでなく、Grafana の可視化ライブラリを使って視覚的に\_表示\_します
* これにより信頼性が高まり、LLM が陥りがちな長文テキストの羅列を避けられます

**次のステップの提案ボタン** が表示されたとき

* ほとんどの場合、Assistant はフォローアップの質問やアクションを提案します。または、そのままプロンプトを入力し直すこともできます

## 質問

**Frontend O11y データのクエリ**

1. フロントエンドアプリ ecommerce について、過去 3 時間のページ読み込み数を教えてください。
2. それらのページにエラーはありますか？
- ___エクストラクレジット___

    3. Frontend O11y の質問をもう 1 つ行います。今回はログデータソースを参照するために `@` コンテキストを指定してください。データソースは grafanacloud-\*\*\*\*\*-logs です。
    4. Frontend O11y の質問をもう 1 つ行います。今回は `@` コンテキストを使って、ログラベル app_id（1 つのみ）を選択してください。このラベルは Frontend O11y がどのアプリかを指定するために使用されます。データソースは grafanacloud-\*\*\*\*\*-logs です。

    6. ecommerce Namespace のアプリケーションとインフラストラクチャのみを対象とするルールを作成してみてください（自分用）
